# V2: the new look (2.0, launched 2026-11-10)

V2 is the new look for all four builds: the Knomi, Mac, Windows and the web. It was built on the `v2` branch, cut
from `knomi-v2` at 1.51, and launched as 2.0 on 2026-11-10 (Fedor: "Lets go V2!"): the firmware, PokeMacGochi and
PokeWinGochi all 2.0. The approved designs, mockups and the screen
checklist are in the roadmap session's notes (`v2-prep/`: `README.md`, `ASSETS.md`, `mockups/`, `review/`, `scripts/`).

## The switch

Everything new sits behind one build flag, `UI_V2`: `1` (the default on this branch, set in `ui_v2.h`) draws V2, `0`
draws 1.51's screens. Nothing in the save depends on it.

- With `UI_V2=0` the game compiles to exactly 1.51's code: the preprocessed sketch is identical, and the Knomi's
  `firmware.bin` comes out the same size as 1.51's.
- V2's code is in `scene_v2.h` (and the walk in `walk_v2.h`, which it includes), with the positions in `layout_v2.h`,
  the colours in `palettes_v2.h` and the scenery in `sprites_v2.h`. The sketch includes `scene_v2.h` just before
  `render()`, so it can use the drawing helpers. `sdmon.cpp` reads the flag too, for the walk's sprite rows.

| Build | V2 (default) | V1 |
|---|---|---|
| Knomi | `arduino-cli compile ... --build-property "compiler.cpp.extra_flags=-DBOARD_KNOMI_V2"` | add `-DUI_V2=0` to those flags |
| Mac | `zsh mac/build_app.sh` | `UI_V2=0 zsh mac/build_app.sh` (rebuilds the host library) |
| Windows | `zsh windows/build.sh` | `UI_V2=0 zsh windows/build.sh` |
| Web | `WEB_OUT=build/web-v2 zsh webgame/build.sh` | `UI_V2=0 WEB_OUT=build/web-v1 zsh webgame/build.sh` |

`WEB_OUT` keeps a test build out of `web/play`, which is what gets published. A copy served from localhost doesn't
join the buddy relay unless the address has `?relay=1`, just as Mac and Windows test copies need `POKEMACGOCHI_RELAY=1`.
The Wi-Fi is the other way in: a Mac or Windows copy, and the screenshot tool, talk to the Knomis on the same network
on their own port unless they run with `POKEMACGOCHI_BUDDY_PORT=47391`. With both, a test pet never turns up beside
the real ones at home. (The host tests switch the network off themselves.)

## A standalone game (Fedor, 2026-11-07)

The game that inspired this one is credited once, in a thank-you at the README's end (and its author in
`LICENSE`, as MIT requires). The Waveshare web installer, which still flashed that game's own 1.18 firmware, is
gone; the code still builds for that board (`docs/WAVESHARE.md`), and Fedor will come back to it when he has the
screens.

The save has a name of its own: "pokeknomigochi" (`savename.h`; V1 keeps the old one, `SAVE_NS_OLD`). On V2's first start
(`saveMigrate()`, the first thing in `setup()`), a Knomi copies every entry of the old NVS namespace into the new
one and marks it done in a namespace of its own ("pkgsave", which starting over doesn't clear); the old namespace
stays as it was, so going back to 1.51 finds its save. If the copy can't finish (the NVS too full), that run plays
on the old namespace and the next start tries again. On a computer and the web, while the save folder has no
`pokeknomigochi.prefs`, the old name's file is read as the new save and written under the new name at the next save,
the old file left as it was. Starting over in V2 clears the old save too, so it can't come back. PokeWebGochi's
export and import use the new file.
Before launch (Fedor: "how can we make sure that the current saves on everyone's games will carry over?"): the copy
checks the NVS's `available_entries`, not `free_entries`, which counts the page the NVS keeps empty for itself, and
a copy that stops half way is erased again, so it can't hold the room the old save needs to go on being saved. Fedor's
Knomi (its backup of Nov 3) had 264 of 630 entries written, the save 58 of them; a 1.51 save of 64 keys takes about
74, so the copy has room to spare. V2 reads every key V1 writes the same way and only adds eight (the Master and
Ultra Balls' bars and counts, the Repel, `pkok`), each 0 when it's missing. A copy of a real 1.51 save from the
Mac (Blastoise at 100, 149 registered) came up the same in V2: 63 of its 64 keys byte for byte, the 64th the clock
it was last seen at, the old file untouched.
